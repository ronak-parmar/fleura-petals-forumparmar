Starting point

From a single page to a working ordering platform.

Today Fleuréa Petals is one static marketing page — a palette, a wordmark, and copy about ribbon-wound blooms and same-day fresh flowers. This plan grows that into a minimal e-commerce site: browse a catalogue, fill a cart, place an order, request a custom bouquet, and let the owner manage it all from a small admin panel.

Optional accounts Minimal admin panel Multi-item cart Custom-bouquet requests Payment gateway

System shape

Three tiers, one repository.

The stack is fixed by the project report: a Next.js front end talking to an ASP.NET Core Web API over REST, with PostgreSQL behind it. Nothing exotic — the work is in the middle tier.

Catalogue logic

The catalogue has two natures.

The existing site already splits the offer in two: everlasting ribbon / pipe-cleaner / silk blooms, and fleeting same-day fresh arrangements. That single nature field on a product drives both the shop filter and the checkout date rules.

Everlasting nature = everlasting

Hand-wound ribbon, pipe-cleaner posies, silk event bouquets. Made to order, so each product carries a lead_time_days. Checkout blocks dates sooner than that.

Fresh & gifted nature = fresh

Seasonal stems sourced the morning they are gifted, optionally paired with a gift. Checkout allows next-day at the earliest and flags same-day as a call-to-confirm.

State & lifecycle

Two things move through states.

An order marches forward through fulfilment; a custom request loops through review and quoting until it is accepted, declined, or turned into a real order.

User journeys

Three paths through the site.

A buyer placing an order, a customer requesting something bespoke, and the owner working the admin panel. These become the use-case and activity diagrams for the report.

Build modules

Eleven modules.

This is the breakdown for report §4.4 — each is a self-contained slice of work with its own screens, endpoints, and test cases.

Catalogue

Categories, product listing, nature/category filters, search, product detail.

Cart

Add / update / remove items, localStorage persistence, live re-pricing against the API.

Checkout & Order

Contact + delivery capture, delivery-date rules, order creation in one transaction, confirmation, guest tracking.

Custom Request

Bespoke bouquet enquiry form, optional inspiration image, request tracking, lifecycle.

Customer Account

Optional register / login, order history, custom-request history, saved addresses.

Admin — Products

Product & category CRUD, availability toggle, image upload, activate / deactivate.

Admin — Orders

Filterable order list, order detail, status transitions, dashboard counts.

Admin — Custom Requests

Review requests, record a response and rough quote, advance status.

Enquiries

Footer contact form plus an admin list with a mark-handled action.

Boundaries

What is in, and what is deliberately not.

The right-hand column belongs in the report's Scope section too — documented limits are not gaps.

In scope

  • Catalogue with category / nature filters and search
  • Multi-item cart, persisted client-side
  • Guest checkout with delivery date and slot
  • Order confirmation and guest order tracking
  • Custom bouquet request flow with tracking
  • Optional customer accounts and order history
  • Admin panel: products, orders, custom requests, enquiries
  • Dashboard counts

Out of scope

  • Any payment gateway — orders are pay-on-delivery
  • Real stock counts — products have availability states only
  • Automated email / SMS — notifications are on-screen
  • Delivery routing, maps, courier integration, live tracking
  • Reviews, ratings, wishlists, coupons, loyalty
  • Multi-admin roles and permissions
  • Multi-currency
